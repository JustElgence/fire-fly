# 📱 手机发布文章指南

不依赖电脑、不依赖 Studio 表单，手机浏览器 5 分钟发一篇文章。

## 一句话原理

文章 = 仓库里 `src/content/posts/` 下的一个 Markdown 文件。手机上在 GitHub 网页新建这个文件并提交，再去 Studio 点一下构建，文章就上线了。

## 发布步骤

### 1. 新建文件（收藏这个直达链接）

在手机浏览器打开：

```
https://github.com/JustElgence/fire-fly/new/main/src/content/posts
```

（这是「在 posts 目录新建文件」的直达页，建议收藏到手机主屏幕）

- 用你的 JustElgence 账号登录后，页面直接就是文件编辑器（顶部填文件名，中间写内容）
- 文件名建议：`日期-短横线英文或拼音.md`，例如 `2026-10-30-weekend-hangzhou.md`
  - 不要用中文文件名：它会变成文章链接里的一长串编码
  - 文件名就是文章链接（slug），起个自己认得的名字就行

### 2. 粘贴模板并填写

打开仓库里的 [docs/文章模板.md](./文章模板.md)，全选复制粘贴进编辑器，然后：

| 字段 | 说明 |
|---|---|
| `title` | 改成本篇标题（必改） |
| `published` | 改成当天日期 `YYYY-MM-DD`（必改） |
| `description` | 一句话摘要，显示在列表页和分享卡片（建议写） |
| `category` | 分类，如 `日常`、`美食`、`旅行`；写新分类会自动创建 |
| `tags` | 方括号里逗号分隔 |
| `draft` | `true` = 草稿（不出现在站点），写完记得改回 `false` |
| `pinned` | `true` = 置顶 |
| `comment` | `false` = 这篇文章关闭评论区 |

### 3. 提交

页面拉到底 → Commit message 随便写（如 `content: 新文章 xxx`）→ 选 **Commit directly to the main branch** → **Commit changes**

### 4. 构建（就差这一下）

回到 **Studio → 构建状态 → 点构建**，几十秒后文章上线。

> 想跳过这一步实现「提交即发布」？那需要给服务器接一个自动构建触发，属于后续升级项。

## 常见问题

- **想存草稿**：`draft: true` 提交，写完改 `false` 再构建
- **加封面图**：图片建议先用图床（你动态里用的外链图床就行），把 `image` 填成图片直链；或 `image: ""` 留空无封面
- **写错了要改**：GitHub 网页打开那篇文章的文件 → 铅笔图标编辑 → 再提交再构建
- **发布反悔**：把 `draft: true` 即可下线，不用删文件

## 更省事：Memos 里写，一条命令转正（推荐）

手机上最舒服的写作入口还是 Memos（随手写、随手改）。写好后一条命令把它转正为文章：

```bash
pnpm memo-to-post --list                      # 列出最近动态，拿 memo 链接或 ID
pnpm memo-to-post https://memos.teardrop.cn/m/<ID> --draft
```

- 首行自动变标题，正文里的 `#标签` 自动收进文章 tags（正文原样保留）
- 可选：`--title` 指定标题、`--category` 分类（默认「日常」）、`--description` 摘要、`--dry-run` 只预览不落盘
- 转正后 Memos 原文不动；生成的是草稿或正常文章文件，照旧去 Studio 点构建

> 建议搭配：Memos 里先写 → 想发布就转正 → Studio 构建；不想发布的碎碎念就留在动态里，本来就该在那儿。

## 电脑上写长文（补充）

长文还是推荐电脑：仓库根目录 `pnpm new-post 文件名` 生成骨架 → `pnpm dev` 本地实时预览 → 写完 push，同样去 Studio 点构建。
