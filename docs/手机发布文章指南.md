# ✍️ 文章发布指南：写作入口只在 Memos

文章和动态用同一个入口写——**手机 Memos 随手写**。区别只有一个：想让某条内容变成文章，就在正文里带上 **`#转文章`** 标记。

## 日常流程（两步，写完就不用管了）

1. **Memos 里写正文**，带上 `#转文章` 标记（放哪都行，会被自动剔除，不会出现在文章里）：

   ```
   周末去了西湖，人比鱼多。
   （正文……）
   #杭州 #周末 #转文章
   ```

2. **等自动转正 + 自动构建**：仓库的 GitHub Actions 每 30 分钟扫一次，把带标记的动态转成文章提交进仓库，**并自动触发构建台构建**。急用就到仓库 Actions 页面点 **Memos 转文章 → Run workflow**，几十秒完成转正，构建随后自动开始。

之后不用任何操作，文章自动上线（构建约 3~5 分钟）。

> Studio 里的「发布并构建」按钮不用了，留作手动兑底（自动构建失败时用它补救）。

## 规则速查

| 你想做的 | 怎么做 |
|---|---|
| 写成文章 | 正文带 `#转文章` |
| 只当动态 | 不带标记（永远是动态） |
| 给文章加标签 | 正文里写 `#标签名`，会自动进文章标签 |
| 改已发布的文章 | **直接在 Memos 里编辑那条 memo**（保留 `#转文章` 标记），下次扫描自动重新同步，文章链接不变 |
| 文章标题 | **正文第一行文字就是标题**（图片行会自动跳过），写的时候把标题放首行 |
| 长文/草稿 | Memos 里写到哪算哪，不放心就先不带标记；想正式点再用电脑 `--draft` 转（见下） |
| 立即转正 | 仓库 Actions 页面 Run workflow，或电脑跑 `pnpm memo-to-post --auto` |
| 只预览不落盘 | 电脑跑 `pnpm memo-to-post <ID> --dry-run` |

## 电脑端手动控制（可选）

```bash
pnpm memo-to-post --list                     # 列出最近动态
pnpm memo-to-post --auto                     # 立即跑一次自动扫描
pnpm memo-to-post <ID> --draft               # 手动转一条并存为草稿
pnpm memo-to-post <ID> --dry-run             # 预览生成的文章
```

## 背后发生了什么

- Actions 定时跑 `pnpm memo-to-post --auto`：拉取 Memos 列表 → 找带 `#转文章` 的新动态 → 生成 `src/content/posts/日期-xxxxxx.md`（与构建台同风格）→ 提交进仓库
- 每条 memo 只转正一次，状态记在 `.memo-to-post-state.json`；检测到 memo 被编辑（updateTime 变化）会用**同一个文件**重新同步，文章链接永远不变
- Memos 原文永远不动，转正是「复制」不是「搬运」

## 排查

- **转正没发生**：确认正文里有 `#转文章`（`#转文章啦` 这种连写的不会触发）；看仓库 Actions 页「Memos 转文章」的运行日志
- **改了 memo 没同步**：确认编辑后标记还在；Actions 最快 30 分钟后扫到，急就手动 Run workflow
- **文章上线还差一步？**：现在转正后会自动触发构建（需要仓库 Secret `STUDIO_TOKEN` = 构建台访问令牌，设一次即可）。如果 Actions 报「触发构建失败」，检查这个 Secret；临时补救用 Studio 手动点「发布并构建」
